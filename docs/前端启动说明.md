# 前端启动说明

本文档说明如何在本地启动当前合并预览版本的前端。

## 目录说明

当前本地预览代码放在：

```powershell
C:\Users\ROG\Desktop\capstone\New
```

其中：

- `New\frontend`：主前端，也就是产品介绍页。技术栈是 Next/Vinext。
- `New\trip`：同事分支中的登录后旅行工作台界面。技术栈是 Vite + React。
- `New\frontend\public\trip-app`：已经构建好的 `trip` 静态版本，用于在主前端 `/trip` 页面中预览。

## 首次安装依赖

打开 PowerShell，进入主前端目录：

```powershell
cd C:\Users\ROG\Desktop\capstone\New\frontend
npm install
```

如果需要重新构建同事的 `trip` 子应用，进入：

```powershell
cd C:\Users\ROG\Desktop\capstone\New\trip
npm install
npm run build
```

然后把 `trip` 的构建结果复制到主前端：

```powershell
Copy-Item -Path C:\Users\ROG\Desktop\capstone\New\trip\dist\* -Destination C:\Users\ROG\Desktop\capstone\New\frontend\public\trip-app -Recurse -Force
```

## 启动主前端

在 PowerShell 中运行：

```powershell
cd C:\Users\ROG\Desktop\capstone\New\frontend
$env:WRANGLER_LOG_PATH=".wrangler/wrangler.log"
npx vinext dev
```

如果 3000 端口被占用，可以指定其他端口：

```powershell
npx vinext dev --port 3001
```

## 访问页面

默认启动后访问：

```text
http://localhost:3000
```

主要页面：

- `http://localhost:3000/`：产品介绍首页。
- `http://localhost:3000/login`：本地演示登录页。
- `http://localhost:3000/trip`：登录后的旅行工作台预览页面。
- `http://localhost:3000/trip-app/`：同事的 `trip` 子应用静态入口。

## 当前合并方式

这次本地预览没有把两个前端强行合成一个 React 项目。原因是两个分支的技术栈不同：

- 主前端使用 Next/Vinext、React 19。
- `trip` 工作台使用 Vite、React 18、React Router。

为了先让你看效果，当前采用更稳的方式：

1. 主前端保留产品介绍页。
2. 新增 `/login` 作为本地演示登录入口。
3. 新增 `/trip` 页面。
4. `/trip` 用 iframe 加载 `public/trip-app/` 中的工作台静态构建。

这样可以先验证视觉和流程，后续再决定是否真正统一技术栈、路由、登录状态和数据模型。

## 常见问题

### npm run build 在 Windows 下失败

主前端 `package.json` 中的 build 脚本使用了 Unix 风格环境变量：

```text
WRANGLER_LOG_PATH=.wrangler/wrangler.log vinext build
```

PowerShell 不支持这种写法。请改用：

```powershell
$env:WRANGLER_LOG_PATH=".wrangler/wrangler.log"
npx vinext build
```

### /trip 页面空白

先确认 `trip` 子应用已经构建，并且 `New\frontend\public\trip-app` 中存在：

```text
index.html
assets\
```

如果不存在，重新运行：

```powershell
cd C:\Users\ROG\Desktop\capstone\New\trip
npm run build
Copy-Item -Path C:\Users\ROG\Desktop\capstone\New\trip\dist\* -Destination C:\Users\ROG\Desktop\capstone\New\frontend\public\trip-app -Recurse -Force
```

### npm audit 显示 vulnerabilities

当前依赖安装时可能显示 audit 警告。这个不会阻止本地预览启动。后续正式合并前，再单独评估是否升级依赖，避免为了修复 audit 警告引入破坏性版本变化。
